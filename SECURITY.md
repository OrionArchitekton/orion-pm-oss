# Security scope

This package coordinates cooperating local clients. It is not access control or
isolation against another process running as the same user. Use a private local
store and each action executor's own authentication, approvals and native leases.
Untrusted task text/evidence never grants authority or triggers fetching/execution.

Report a reproducible issue privately to the project owner through an established
private channel. Do not include credentials, private boards, accounts, handoffs,
profiles or personal paths in a public issue. There is no dedicated public security contact or response-time commitment yet.

Contain unsafe state by stopping sanctioned writers, preserving a private offline
copy, and following the local-store runbook. Never solve a corrupt claim by deleting
live ownership or assuming an expired process stopped. Keep unsupported storage
and cross-host execution outside the safety claims.
